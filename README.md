# leveltrust

徕卡 DNA03 数字水准仪原始记录(`.DAT`,GBK)的**真实性筛查**工具。纯标准库,Python ≥ 3.10。

```bash
python3 -m leveltrust check  data.zip            # 或目录 / 单个 .DAT;--json 输出机读结果
python3 -m leveltrust seal   data.zip -o m.json --key <口令>   # 导出后立刻封存基线
python3 -m leveltrust verify m.json  data.zip --key <口令>     # 之后随时比对,指出变动行
python3 -m unittest -q tests.test_leveltrust
```

## 检查分层(证据由弱到强)
| 层 | 内容 | 能说明什么 |
|---|---|---|
| L1 容器/时间 | ZIP CRC、文件保存时间 vs 表头观测时段 | 观测结束后是否被再次保存 |
| L2 文本层 | 换行符、编码、各类记录的固定列宽 | 是否被文本编辑器手工改过(同宽度改数字发现不了) |
| L3 算术冗余 | `Z = Z前 + Rb̄ − Rf̄`、`Z中间 = 仪器高 − Rz`、视距总和、Adr 连续、时间单调 | 读数与派生量被单独改动 |
| L4 流程/物理 | 站间搬站时间、前后视同一尺位、视距差、闭合差 | 数据是否符合真实作业 |
| L5 跨文件 | 同仪器时钟偏差、时段重叠、同观测者重叠 | 表头/时间被后填 |
| L6 统计 | 读数末位均匀性 | 仅作参考,样本小时不下结论 |

**唯一能"证明文件被改过"的是 `seal`/`verify`**(SHA-256 + 逐行哈希 + 可选 HMAC)。
基线要在仪器导出后立刻做,并把清单交给第三方(邮件、git 提交、时间戳服务)。

## 边界
通过全部检查 ≠ 真实:程序按公式生成并重算 Z、或改后重新导出,本工具发现不了。
最终仲裁依据是仪器内存原始数据、导出日志与现场独立证据。所有疑点都附"可能的正常原因"。
